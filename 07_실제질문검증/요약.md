서버 cap-vdb, Milvus 2.6.23, nq_seq(100만 조각, 64단어), 평소 상태(캐시 따뜻함). 측정 중 다른 계정의 새 프로세스 없음, 오류 0.
코드: gold_map.py, analyze_pf3.py, bench_pf3.py, pf3_rules.py, run_pf3.sh (w12실험\코드). 전체 묶음: 코드\pf3_results_1116_1051.tgz

## 정답 근거 복원 검증
- 다시 만든 조각 1,000,000개를 chunks.jsonl과 전부 대조했다. 다른 것은 0개였다.
- 정답 문단(qrels) 4,201개가 모두 우리 조각 안에 통째로 들어 있었다. 저장된 조각 글 안에 문단 글이 그대로 있는지도 4,201개 전부 확인했다.
- 평가에 쓴 질문
  - 정답 문단 기준: NQ 실제 질문 3,452개 전부
  - 정답 문자열 기준: nq_open에서 같은 질문을 찾은 2,254개
- 눈으로 확인할 샘플은 gold_samples_nq.txt에 30개가 있다.

## 1. 이웃이 실제로 필요한가 (NQ)
| | top-10만 | + 이웃 전부 |
|---|---|---|
| 정답 문자열이 읽은 글에 있음 (2,254개) | 78.1% | 87.7% |
| 정답 문단 단어 중 읽은 비율 | 51.4% | 72.0% |
| 정답 문단을 통째로 읽음 | 31.6% | 67.5% |
| 정답 문단 조각을 하나라도 읽음 | 75.6% | 80.6% |

- **이웃까지 읽어야 정답 문자열이 들어오는 질문: 9.6%.**
- 이웃 조각에 정답 문자열이 있는 질문은 49.6%였다. 그중 81%는 이미 top-10에 정답이 있었다. "이웃에 정답이 있음"과 "이웃이 필요함"은 다르다.
- top-10에는 정답 문단이 없고 이웃에만 있는 질문은 5.0%였다.

## 2. 규칙별 선택 (정답을 보지 않고 고름)
"정답 이득 유지"는 이웃까지 읽어야 정답이 들어오는 질문 중 그 규칙이 정답을 가져온 비율이다.

| 규칙 | 읽는 조각/요청 | 고른 이웃 비율 | 정답 포함 | 정답 이득 유지 |
|---|---|---|---|---|
| none (top-10만) | 10.0 | 0% | 78.1% | 0% |
| C1 1위의 이웃 | 11.2 | 8% | 81.1% | 32% |
| C3 상위 3개의 이웃 | 13.9 | 27% | 83.3% | 54% |
| B 같은 문서 2개 이상 | 18.4 | 57% | 86.1% | 84% |
| BC1 B + 1위 | 18.7 | 59% | 86.7% | 89% |
| A 잘린 문장 잇기 | 24.3 | 97% | 87.4% | 98% |
| all 이웃 전부 | 24.7 | 100% | 87.7% | 100% |

- 규칙 A는 이웃을 97% 골라서 all과 같다. 64단어 고정 조각은 4.2%만 문장 끝으로 끝나기 때문이다.
- 고른 이웃 중 정답 문단이 들어 있는 비율(precision)은 모든 규칙에서 5~18%로 낮다.
- 검색 점수나 top-10의 문서 분포로 "이웃 필요"를 미리 맞히는 것은 거의 안 됐다(AUC 0.43~0.57).

| 정책 | 평균 ms | none 대비 (95% 구간) |
|---|---|---|
| none | 9.92 | |
| all | 10.18 | +0.26 ± 0.17 |

- 무작위 필요 비율 실험(pf2)에서 잰 손익분기 p*는 회차별로 0.073, 0.092, 0.090이었다. 실제 필요 비율 9.6%는 그 근처다.
- 따뜻한 캐시에서는 조각을 더 읽는 비용이 0.3ms 안팎이었고, 규칙끼리는 차이가 없었다. 시간을 좌우하는 것은 읽는 조각 수가 아니라 호출 수다.

# C3 파이프라인 측정 설계 v3.1 (2026-11-23, 측정 전 추가) — 2026-11-23 확정 (측정 전, QPS 보기 전)

v3(`C3_파이프라인측정_설계_v3.md`, 2026-11-23 고정)는 그대로 둔다. v3.1은 v3에 아래 두 가지만 더한다. 나머지 조건·순서·판정·보고 규칙은 v3와 같다.
- 시점: 서버에서 스위치 status 출력과 nq_seq load 상태만 읽었고, 측정 QPS는 한 번도 보지 않은 상태에서 정함.

## 추가 1: 세션 유효 조건 V5 (스위치 제한)
- V5 성능 6번(정확성 실행 포함 9번 모두)의 앞·뒤 스위치 status에 **제한이 걸려 있지 않음**. 하나라도 걸려 있으면 세션 "판정 불가".
- "제한이 걸려 있다"의 정의 (2026-11-23 status 출력 형식 기준):
  - `memory.current ... memory.high <값>  memory.max <값>` 줄에서 `memory.high` 또는 `memory.max` 값이 `max`가 아니면 걸린 것.
  - `io.max:` 줄의 콜론 뒤(같은 줄), 또는 그다음 줄부터 `floor for mem:` 줄 전까지에 공백이 아닌 내용이 있으면 걸린 것.
    (제한이 없을 때 출력: `io.max:` 뒤에 아무것도 없고 바로 다음 줄이 `floor for mem: ...`)
  - status 파일이 없거나 `memory.high`·`io.max:`를 찾지 못하면 "확인 못 함" → 판정 불가.
  - 실행 앞뒤 값이 달라졌는지는 따로 보지 않는다: 앞이나 뒤 어느 한쪽이라도 걸려 있으면 위 정의로 잡힌다.
    앞뒤 모두 제한 없음인데 실행 도중에만 걸렸다 풀린 경우는 못 잡는다(한계).
- 근거: 스위치는 팀 공용 Milvus의 제한(mem, iops)을 바꾼다. 실행기에서 reset을 뺐으므로, 남이 건 제한이 측정 중에 있으면 m3·m7이 다른 조건에서 잰 값이 된다.

## 추가 2: 실행 안내
- 측정 직전 단톡방에 "○시~○시 Milvus 측정(nq_seq), 이 시간 스위치 제한 변경 자제"를 알린다. 시간대는 `WINDOW`와 같게.
- 실행 전 nq_seq가 Loaded면(2026-11-23 저녁 확인 시 Loaded) check_busy가 "조용함"일 때 소유자가 release하고 NotLoad를 확인한 뒤 시작한다.
  단톡방 안내에 "측정 중 nq_seq release, 끝나면 다시 load"를 넣는다.
- 측정이 끝나면 nq_seq를 측정 전 상태로 되돌린다: 측정 전에 Loaded였으면 다시 load하고 Loaded를 확인한다(실행기의 MilvusGuard는 자기가 load한 것만 release하므로, 끝나면 NotLoad로 남는다).
- 스위치 status를 못 읽으면(출력에 memory.high 줄이 없으면) 5초 뒤 한 번 더 읽는다. 두 번 다 실패하면 "확인 못 함"(V5·V4 판정 불가).
- 위 세 가지는 실행 절차이고 판정 규칙(V1~V5, 판정, 보고)은 바꾸지 않는다.

## 비용
- 실행 하나만 걸려도 세션 전체(약 30분)를 다시 해야 한다. 조건이 다른 결과를 섞는 것보다 낫다고 보고 감수한다.

- **세션 유효 조건** (하나라도 어기면 "판정 불가", 결과는 모두 보고)

  - V3 6번 모두 종료 코드 0, 오류 0, checks 위반 0
  - V4 각 실행 앞뒤 스위치 status의 OOM 기록이 늘지 않음
- **판정** (유효한 세션만, 여유폭 0)
  - "상한 8 쪽으로 3쌍 일치" = r_1, r_2, r_3 모두 > 1
  - "제한 없음 쪽으로 3쌍 일치" = r_1, r_2, r_3 모두 < 1
  - 나머지 = "방향 일치 안 함"
- **보고용 규칙** (판정을 바꾸지 않음)
  - r 값 3개와 최솟값(제한 없음 쪽이면 최댓값)을 그대로 적는다.
  - 실제 차이가 없어도 3쌍이 우연히 한 방향으로 모일 확률은 양쪽 합쳐 1/4(쌍 독립 가정)이라고 적는다.
  - r 최솟값 < 1.01이면 strict_qps로 계산한 r 3개도 적는다(측정 구간 뒤 꼬리 요청이 m3 쪽에 1% 미만 더 들어가는 문제).
  - "흔들림 큼" 표시: max(m3 3회 QPS 범위, m7 3회 QPS 범위) > min(쌍별 |m7 − m3|)이면 붙인다. 범위 = 최댓값 − 최솟값(QPS).
  - p50/p95/p99, queue_wait는 적기만 한다.
  - 순서상 m3가 먼저인 쌍이 2개라, 처리량이 시간에 따라 계속 떨어지면 m3에 약간 유리하다(m7 판정에 보수적)고 적는다.
- 판정은 내부 기준이다. 통계적 입증으로 쓰지 않는다. 발표에서는 "3쌍 모두 같은 방향, r 최솟값 ○○"까지만 말한다.
- 재측정을 여러 번 하면 처음으로 유효한 세션 하나로 판정한다.

# REPORT_v3: FiQA에서 후보 선별 방식의 유효성 확인

- 2026-11-22, `/workspace/jaeeun/sel_fetch_v3/`. 규칙은 PLAN_v3.md에 결과 보기 전에 고정했고 변경하지 않았다.
- FiQA: 133,919 chunk, numpy 정확 검색 Top-100, v2와 같은 cross-encoder로 Top-100 전체 Rerank (GPU0, 5.1 q/s). Milvus는 쓰지 않았다.
- 주 결과는 FiQA test 648개, A1·B1은 NQ dev에서 정한 값 그대로. 통계는 질문 단위 paired bootstrap 2,000회.

## 최종 판단
| 질문 | 답 | 근거 |
|---|---|---|
| 1. A1이나 B1을 학습 없는 선별 방식으로 채택할 근거가 있나 | **품질 개선 방식으로는 없다.** "학습 없이 M1-noPos와 동등한 대안"이라는 근거만 NQ에서 성립한다 | NQ: A1·B1 = M1-noPos (차이의 CI가 0 포함), Top-B 대비 +0.006~0.007. FiQA test: 모든 B에서 Top-B보다 높다는 근거 없음. A1@10은 오히려 나쁨 (−0.011 [−.019, −.002]) |
| 2. Top-B보다 유리한 조건이 있나 | **이번 두 데이터에서는 실질적으로 없다.** 유리해지려면 세 조건이 함께 필요하다는 것을 확인했다: (i) Reranker가 ANN 순서보다 실제로 품질을 높일 것, (ii) Top-B가 B≈10~15에서 포화되지 않을 것, (iii) A1의 경우 Top-B 밖 중요 후보가 Top-B와 같은 문서에 있을 것 | NQ는 (i)과 (iii)을 만족하지만 (ii)가 B≈20에서 포화돼 이득이 0.01 미만. FiQA는 (i)이 깨짐 (전체 Rerank − ANN 순서 = −0.0095 [−.029, .008]), (iii)도 13%로 NQ 53%보다 크게 낮음 |
| 3. 독립 기여인가, 파이프라인 구성 요소인가 | **구성 요소로 두는 것이 타당하다** | 지연시간 이득은 \|S\|(Rerank 예산) 축소에서 나오고 Top-B로 충분하다 (NQ e2e). 선별 알고리즘의 품질 이득은 데이터마다 다르고 0.01 미만이다. 독립 기여로 주장하려면 위 (i)~(iii)을 만족하는 데이터에서 다시 보여야 한다 |

## 4단계 분석: 선별 효과를 좌우하는 데이터 특성
| 특성 (test) | NQ | FiQA | 선별에 미치는 영향 |
|---|---|---|---|
| 문서당 chunk 수 | 36.9 | 2.3 | A1의 재료 |
| Top-B 밖 기준 Top-10이 Top-20과 같은 문서에 있는 비율 | **52.9%** | **13.0%** | A1이 찾을 수 있는 후보의 상한. FiQA에서는 거의 없음 |
| 기준 Top-10 중 ANN ≥20 출신 비율 | 31.2% | 45.9% | ANN과 Reranker의 불일치 (FiQA가 더 큼) |
| Kendall τ (ANN vs CE, Top-100) | 0.346 | 0.261 | 〃 |
| Top-100 안의 서로 다른 문서 수 | 46.0 | 86.9 | FiQA는 문서가 분산돼 있음 |
| 전체 Rerank − ANN 순서 (중복 제거 nDCG) | +0.05 (raw, v1) | **−0.0095** (CI가 0 포함) | **Reranker가 품질을 올리지 못하면, Reranker가 중요하다고 볼 후보를 찾는 것 자체가 품질 이득이 되지 않는다** |
| B=20 포화도 | 98.5% | 103.6% | 둘 다 포화. FiQA는 \|S\|를 늘릴수록 손해 |

- **핵심:** FiQA에서는 ANN과 Reranker의 순위 불일치가 더 큰데도 선별 이득이 없었다. 불일치가 Reranker의 정답성에서 나온 것이 아니라 도메인 부적합(ms-marco Reranker를 금융 질문에 적용)에서 나왔기 때문이다. "Top-B 밖의 Rerank 상위 후보 회수"는 Reranker가 정답에 가까울 때만 품질로 이어진다.
- **사례 (B=20):** FiQA에서 이득이 큰 질문 8개를 보면, 새로 들어온 정답 문서는 대부분 **Top-B와 다른 문서**였다 (NQ에서는 6개 사례 모두 같은 문서). A1은 다른 문서의 후보를 문서 점수로 끌어올렸고, B1은 CE 상위 3개와 임베딩 유사도 0.6~0.7인 후보를 골랐다. 하지만 평균으로 보면 손해와 이득이 상쇄된다.
- **M1-noPos(a)가 FiQA에서 버틴 이유 (가설):** 이 모델은 "ANN 순위 + 후보 간 임베딩 관계"를 비선형으로 학습했고, 이 신호가 도메인과 무관하게 옮겨진 것으로 보인다 (FiQA test에서 순위 AUC 0.662 → M1a 0.702). 그래도 test 단독으로는 판단 불가이고, dev+test의 유의 결과는 30여 개 비교 중 하나라 우연일 가능성을 배제할 수 없다.

## ConStore SICP와의 차이 (arXiv 2610.21676을 직접 확인함. 확인 범위: HTML의 §1~§5.2는 원문, 그 뒤는 요약본)
ConStore의 SICP(Speculative Inline Content Prefetch)는 **ANN 검색 도중** 백그라운드 worker가 후보 스냅샷을 읽는 방식이다. DiskANN에서는 hop 간격, SPANN에서는 posting 처리량 간격으로 스냅샷을 받는다. 상위 후보 집합이 몇 번 연속 안정되면 상위 K·α개의 본문을 **I/O 예산 안에서 미리 읽는다** (prefetch 횟수, 회당 문서 수, 회당 I/O 예산의 세 단계로 제한). 검색 순서와 최종 Top-K는 바꾸지 않고("final top-K is authoritative"), 빗나간 prefetch만큼 추가 I/O가 생긴다. Query Log나 학습 없이 문서→extent 조회만 쓴다. 반면 우리 선별은 **ANN 검색이 끝난 뒤** Top-100 중 어떤 후보를 Fetch하고 **Rerank에 넘길지(\|S\|<100)**를 정해서, 최종 Context 자체와 Rerank 연산량을 바꾼다. 정리하면 SICP는 "정해진 결과의 Fetch 지연을 검색 시간 뒤에 숨기는" 방식이고(결과 동일, 일은 같거나 늘어남), 선별은 "Rerank할 일을 줄이는" 방식이다(결과가 달라질 수 있고, 일이 줄어듦). 둘 다 로그가 필요 없으므로 **로그 사용 여부는 차별점이 아니다.** 둘은 경쟁하기보다 상호 보완적이다 (예: SICP로 선별된 S를 검색 도중 prefetch). **미확인:** SICP의 파라미터 값(K′, α, 예산), ConStore 파이프라인에 cross-encoder Rerank 단계가 있는지(본문에서 찾지 못함), RPAG 그룹 크기 B의 값, §5.2 이후 세부 수치(요약본 기반).

## 한계
- FiQA test 648개로 MDE 약 0.01이라 대부분의 차이가 "판단 불가"다. 결론은 "FiQA에서 유리하다는 근거가 없다"이지 "효과가 없다"가 아니다.
- Reranker 1종(ms-marco)이 FiQA에 맞지 않는다. 더 강하거나 도메인에 맞는 Reranker는 지시에 따라 시험하지 않았다. 이 조건에서는 결론 (i)이 바뀔 수 있다.
- end-to-end는 실측하지 않고 NQ 단가로 환산했다.
- 다중 비교(방법 × B × 집합)를 보정하지 않았다.

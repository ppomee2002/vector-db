## 1단계 확인 결과 (`results_v3/s1/`)
| 항목 | NQ (v2) | FiQA (v3) | 비교 가능? |
|---|---|---|---|
| 데이터 위치 | /workspace/junlim/data_nq | /workspace/junlim/data (C2·C3 브랜치에서 쓴 fiqa_seq와 같은 원본, prep_fiqa.py). qrels는 HF 캐시의 arrow 파일 (읽기만 함) | – |
| chunk | 64단어, 끝 조각 32단어 미만이면 앞에 합침 | 64단어, 끝 조각 16단어 미만이면 합침 (평균 57.2단어) | 거의 같음 |

**검정력:** NQ test에서 질문별 차이(B=20, Top-B 대비)의 표준편차는 0.085~0.103이다. n=648이면 80% 검정력으로 검출할 수 있는 최소 효과(MDE)는 nDCG **0.009~0.011**이다. NQ에서 본 효과(+0.006)는 **검출할 수 없다.** → 차이가 안 나오면 "효과 없음"이 아니라 **"판단 불가"**로 보고한다. FiQA에서 질문별 분산이 다르면 실제 MDE도 달라지므로, 결과에서 실제 SE를 함께 보고한다.

**비교를 왜곡할 수 있는 요인:** (1) 질문 유형: FiQA는 의견·조언형 금융 질문이고 정답 문서가 여러 개인 경우가 많다. (2) 문서 길이: 짧은 포럼 답변이 대부분이다. (3) Reranker(ms-marco-MiniLM)가 금융 도메인에 맞지 않을 수 있다. 이 경우 "기준 Top-10"(전체 Rerank) 자체의 품질이 낮아서, 보존율 기반 해석이 NQ보다 약해진다. (4) chunk 끝 조각 합치는 기준이 약간 다르다. (5) qrels 문서 중 chunk로 매핑되지 않는 비율은 0.06~0.25%로 무시할 수 있다.

**판단:** 비교 조건은 적절하다. 문서 구조가 빈약한 조건에서 같은 방식을 확인하는 것이 이번 목적이고, 검정력 부족은 해석 규칙으로 처리한다. → 2단계로 진행한다.

## 2단계 고정 사항
### 지표
- 품질 (주): **문서 단위 중복 제거 nDCG@10** (최종 Context 10개를 순서대로 훑으며 정답 문서가 처음 나올 때만 이득. 이득은 qrels score(=1). IDCG = min(정답 문서 수, 10)), **정답 문서 포함률 Hit@10**. 정답 문자열은 쓰지 않는다.
- 품질 (보조): 기준 Top-10 보존율, 승격 후보 회수율 (v2와 같은 정의)
- 비용: \|S\|, 선별 계산 시간 (오프라인 실측), Rerank 호출 횟수 (Top-B·A1·M1은 1회, B1은 ⌈B/10⌉회). 지연시간 환산은 NQ e2e 단가를 쓴다: Rerank 1.73ms/후보 (Top-B@30−@20 차이 17.2ms/10), Rerank 호출 고정비는 B1@20−Top-B@20의 Rerank 차이 0.9ms/추가 호출 (warm), Fetch는 warm 0.01ms/후보 수준이라 무시, cold는 0.131ms/블록. **한계:** FiQA chunk 길이와 GPU 상태가 달라서 근사치다.

### 분할
- **주 결과 = FiQA test 648개.** A1·B1은 NQ dev에서 정한 값(A1: maxlog, α=0.3 / B1: β=0.3, γ=0.05)을 그대로 쓴다.
- **보조 (검정력 보강, 결과 보기 전에 정함):** FiQA 데이터를 전혀 쓰지 않은 방법(Top-B, A1/B1의 NQ 값, M1-noPos(a), Random-deep)은 dev+test 1,148개에서도 보고한다.
- 참고: FiQA dev에서 다시 튜닝한 A1·B1 (v2와 같은 격자, B=20 중복 제거 nDCG 최대), M1-noPos(b) = FiQA dev로 학습 (상한 참고치). 이 둘은 test에서만 보고한다.
- M1-noPos(a) = v2의 `m1nopos_dev.joblib` (NQ dev로 학습)을 그대로 적용한다. 피처는 같은 공식이고, FiQA의 chunk 벡터와 문서 구조로 계산한다.

### 판정 규칙
- **포화:** B=20에서 Top-B의 중복 제거 nDCG가 Top-100 전체 Rerank의 98% 이상이면 "포화" (NQ 98.5%, v2 dev 기준).
- **채택 ("유리한 조건이 있다"):** A1 또는 B1이 같은 \|S\|(B=10/15/20/30 중 하나 이상)에서 Top-B보다 중복 제거 nDCG 또는 Hit@10이 높고 95% CI가 0을 포함하지 않으며, 환산 비용 증가가 Top-B 대비 +5% 이하일 때만 인정한다. 여러 B를 보면서 생기는 다중 비교 문제는 보고서에 적는다.
- **판단 불가:** CI가 0을 포함하고 CI 폭의 절반이 NQ 효과(0.006)보다 크면 "판단 불가"로 둔다.

### 예측 (결과와 대조할 것)
| 예측 | 근거 |
|---|---|
| A1은 효과가 약할 것 (Top-B와 차이 없음) | 문서당 chunk 2.3개, 43%가 1-chunk 문서 → 문서 집계에 쓸 재료가 적다 |
| Top-B는 NQ보다 덜 포화될 것 (B=20에서 98% 미만) | 도메인 차이로 ANN과 Reranker 순위가 더 다를 것 |
| M1-noPos(a)는 NQ보다 성능이 떨어질 것, (b)보다 낮을 것 | 로그(학습) 기반 선별은 분포가 바뀌면 옮겨지지 않는다 |
| B1은 A1보다 나을 것 | Rerank 피드백(임베딩 유사도)은 문서 구조에 덜 의존한다 |

## 실행 (3단계)
- 정확 검색: query_vecs(공식 dev/test qi) @ chunk_vecs.T (numpy, float32) → Top-100
- Rerank: v2와 같은 cross-encoder, max_length 256, GPU0, Top-100 전체
- 비교: Top-B, A1, B1, M1-noPos(a), M1-noPos(b), Random-deep (x=⌈0.2B⌉, seed 0), B=10/15/20/30. 통계는 질문 단위 paired bootstrap 2,000회 (seed 0)
- 금지: Milvus, C2 결합, 다른 Reranker, 느린 저장소, 데이터셋 추가, 결과를 본 뒤 규칙 변경

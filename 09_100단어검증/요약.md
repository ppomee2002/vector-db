# 09 100단어 Chunk로 다시 확인 (11/17 09:04~09:43 KST)

목적: 64단어 한 가지 설정에서만 본 결과(규칙 B+C1의 효과)가 Chunk 크기를 바꿔도 유지되는지 확인. 규칙은 미리 고정했다(다시 고르지 않음).
설정과 근거
- 100단어: DPR이 위키백과를 자른 크기. 끝 조각 기준 50단어(64단어 때와 같은 비율, 크기의 절반).
- 같은 글: 64단어 데이터의 문서 27,133개가 그대로 들어가도록 Chunk 수 640,336개를 계산하고, 읽는 문단 양(83,200,000단어)을 64단어 때와 똑같이 맞췄다.
  확인 결과 문단 1,058,932개, 위키 글 36,505개, 문서 27,133개, 문서별 단어 수 모두 같음(마지막 문서만 3,136 -> 3,100단어). 실제 질문 3,452개 같은 순서.
- 임베딩 최대 길이 256: all-MiniLM-L6-v2 모델 카드의 기본값. 64단어 때는 128(100단어 조각은 128 토큰을 넘는 경우가 많아 바꿈).
- 정답 위치 대조: 640,336개 중 다른 것 0개, 정답 문단 4,201개 모두 포함. 정답 문자열 기준 질문 2,254개(64단어 때와 같음).
- 검색: Milvus nq100_seq(HNSW M16, efC200, ef64, 내적), 64단어 때와 같은 설정.
코드: prep_nq100.py(0b1307b1), w100_target.py, w100_check.py, run_w100.sh(d0d0edc8). 결과: w100_results_1117_0043.tgz

- 규칙 B+C1의 효과 유지(89%)와 읽은 Chunk 감소(25%)는 두 크기에서 거의 같았다.

- 규칙 B만 쓰면 100단어에서 효과 유지가 84% -> 80%로 낮아졌다. 1위 이웃을 더한 B+C1이 더 안정적이었다.

## 판정 규칙

- **주 근거는 대조군 비교**예요. 하드웨어는 그대로 두고 기다리는 방식만 바꿨을 때(A→B worker 제한 제거, A→C 병렬 읽기, A→D 둘 다, A→S 비동기 서버) 처리량이 오르면, 원인은 자원이 아니라 대기 구조로 봐요.
- 같은 회차 안의 짝 비교 배수를 회차를 단위로 묶어 기하평균과 95% 신뢰구간(로그 비율의 t 구간)을 냈어요. **신뢰구간 하한 > 1 이면서 배수 ≥ 1.3**일 때만 '확실히 큼'이에요. 회차가 3이면 구간이 넓어서 보수적인 판정이에요.
- 지점별 라벨(보조 근거), 우선순위는 CPU > SSD > 동기식 대기예요.
  - CPU: 서버 CPU ≥ 85%, 또는 CPU를 기다린 흔적(검색 1.5배 이상 느려짐, I/O 단계 중 read 밖 시간 ≥ 30%, read 시간 ≥ 장치 await의 3배)이 있고 Go 스케줄 지연 p99 ≥ 1ms이거나 CPU 대기 스레드가 평균 1개 이상일 때.
  - 저장장치(SSD 또는 가상 디스크): 장치 await ≥ QD1의 2배이면서 장치 큐 ≥ 4일 때. baseline이 장치 한계에 도달한 경우에만 'baseline 최대치의 80%' 규칙도 함께 써요.
  - 동기식 대기: 지연의 30% 이상이 worker 대기이고, worker 제한을 없앤 대조군이 1.3배 이상 빠를 때.
- '안정' 열: 모든 임계값을 ±20% 바꿔도 라벨이 그대로인지 여부예요.

## SSD baseline (O_DIRECT, 서버와 같은 CPU 묶음)

psync는 서버와 같은 방식(스레드당 블로킹 읽기 1개)이고, aio는 스레드 하나가 큐 깊이만큼 비동기 읽기를 유지해요. CPU를 거의 안 쓰므로 aio 최대치가 **SSD 자체의 한계**에 가까워요.

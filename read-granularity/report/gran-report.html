읽기 단위 트레이드오프 실험 결과

벡터 DB가 텍스트(payload)를 저장소에서 읽는 단위를 바꿔 가며, 크게 읽을 때와 작게 읽을 때 각각 어떤 비용이 생기는지 실제 시스템으로 측정했다. Qdrant v1.20.0은 Gridstore payload 읽기 경로에 read 단위 파라미터를 추가했고, Milvus v2.6.23은 Tiered storage의 cell 크기(kRowGroupsPerCell)를 환경 변수로 바꾸게 패치했다.

2026-11-09 · 109 서버 · 데이터셋 NQ (2.68M 문서), FiQA · top-10, 텍스트 반환

요약

양 끝의 기본값Milvus 2.6MB cell, Qdrant 4KB

Milvus는 질의당 S3에서 1.2MB를 읽어 증폭이 약 240배다. Qdrant는 증폭은 작지만 질의당 디스크 I/O가 18~23회다.

크게 읽으면QPS가 1/3 ~ 1/25로 떨어진다

Qdrant를 2MB 단위로 읽으면 로컬 NVMe에서 QPS가 1/3, 공유 디스크에서 1/25이 된다. Milvus는 cell을 1MB로 줄이면 15~46% 빨라진다.

작게 읽으면IOPS 한도에서 자신과 이웃이 느려진다

gp3 수준 디스크에서 4KB는 64KB보다 QPS가 17~21% 낮고, 같은 디스크를 쓰는 이웃의 4KB 읽기 p50을 1.8배로 늘린다.

최적점은 움직인다조건마다 다른 지점

로컬 NVMe에서는 4~64KB가 평평하고, 공유 디스크에서는 64KB가 최적이다. 캐시 예산이 작을수록 큰 단위가 일찍 무너진다.

그림 1. 공유 디스크에서의 U자 곡선 (Qdrant)

Qdrant 컨테이너에 읽기 3000 IOPS, 125MiB/s 상한을 걸었다(AWS gp3 기본 성능). 이웃은 같은 상한 안에서 4KB 랜덤 읽기를 초당 1000회 낸다. 이웃 지연은 원래 보내기로 한 시각부터 재므로, 남의 I/O 뒤에서 기다린 시간이 포함된다.

NQ, 캐시 OFF(payload page 파일을 20ms마다 비움), C=32, 1회. 음영은 최적 구간. 이웃 없이 혼자 읽으면 같은 4KB 읽기가 0.15ms다. 16KB 케이스의 이웃 기록은 프로세스 강제 종료로 빠졌다.

그림 2. 로컬 NVMe, 캐시 OFF (Qdrant)

I/O 한 번이 싼 로컬 NVMe에서는 64KB까지 QPS가 거의 같고, 그 위로는 전송량이 비용을 지배해 단조롭게 떨어진다. 작게 읽는 쪽의 손해는 여기서 보이지 않는다.

캐시 OFF(payload 파일 전체를 20ms마다 비움), natural trace, 2회 반복의 중앙값. 반복 간 차이는 중앙값 2.7%, 90번째 백분위 8.4%다. 4KB 점은 패치 바이너리의 기본 io_uring 경로(G=0)다. G=4096 값(NQ C=32: 968)은 노이즈 범위다.

그림 3. 캐시 예산에 따른 변화 (Qdrant)

컨테이너 메모리를 기준 메모리 + payload의 5% 또는 20%로 묶었다. 큰 단위는 캐시를 낭비해 예산이 작을수록 일찍 무너진다. 1MB는 예산 5%에서 QPS 179(질의당 I/O 482회), 20%에서 424다.

NQ, zipf trace, C=32, 1회. 16~64KB는 질의당 디스크 I/O를 1.6회에서 0.9~1.2회로 줄이지만, 로컬 NVMe라 QPS 이득은 노이즈 범위다. FiQA는 payload가 예산 안에 다 들어가 디스크 I/O가 없어 제외했다.

그림 4. Milvus Tiered storage cell 크기

cell 하나는 Parquet row group(RG) 여러 개다. 기본값은 4 RG(텍스트 cell 평균 2.6MB)이고, 1 RG(평균 0.96MB)가 패치로 갈 수 있는 최소다. 텍스트는 SeaweedFS(S3)에 있고, 요청을 tcpdump로 잡아 Range 헤더로 읽은 바이트를 셌다.

NQ, C=32, 요청 2000건(워밍업 1000건), 1회. 증폭은 S3 읽기 바이트를 반환 텍스트 바이트로 나눈 값이고, 워밍업 요청까지 포함한 근사치다. 8 RG와 16 RG는 실제 cell 크기가 같게 나와서(평균 4.9MB) 8 RG만 표시했다.

해석과 주의점

  • Milvus는 cell을 1MB보다 작게 만들 수 없어서 곡선의 큰 쪽 절반만 보인다. 작은 쪽 손해는 Qdrant 공유 디스크 실험(그림 1)이 담당한다.
  • 캐시 OFF에서 큰 단위로 읽어도 질의당 I/O가 줄지 않는다. top-10 결과가 서로 멀리 떨어져 있어 넓혀 읽어도 합쳐지지 않기 때문이다.
  • stock Qdrant(mmap)는 evictor로 캐시를 비울 수 없어 캐시 OFF 비교에서 제외했다. 비교 기준은 같은 바이너리의 io_uring 기본 경로다.
  • 그림 1의 이웃 있음 조건은 이웃이 같은 cgroup에 들어가서, cgroup 디스크 수치에 이웃 I/O가 섞인다. 질의당 디스크 I/O는 이웃 없음 행만 유효하다.
  • 커널 throttle은 큰 read를 쪼갠 조각 단위로 셀 가능성이 크다. gp3은 256KB까지를 1 IO로 치므로, 256KB 이상은 실제 gp3보다 약간 불리할 수 있다.
  • 그림 1, 3, 4는 1회 측정이다. 그림 2의 반복 간 차이(중앙값 2.7%)를 노이즈 기준으로 보면 된다.

# C3 A 실험: 판정 → 결정 연결표 (결과 보기 전, 2026-11-28 측정 중 작성)

판정 J1~J3은 `C3_A실험_규칙.md`(+v1.1)에 측정 전 고정. 이 파일은 그 판정을 "무엇을 할지/버릴지"로 잇는 규칙이다. 측정은 진행 중이지만 결과 값(QPS·지연·판정)은 하나도 보지 않은 상태에서 작성했다. 결과를 본 뒤 바꾸지 않는다.

| 판정 결과 | 결정 |
|---|---|
| J2가 세 조건 모두 "고르게 증가" | warm에서 동시 실행이 늘 때 특정 단계만 느려지지 않는다 → **Fetch 단계만 조절하는 방식(m6류)은 버림 확정**(warm 기준) |
| J2에서 어떤 조건이 "fetch" | Fetch 단계 조절을 다시 후보로 둔다. 단 12주차 m6(본문 조회만 상한)와 무엇이 다른지(예: C2가 정한 읽기 양을 기준으로 조절) 설명할 수 있을 때만 진행 |
| J2에서 어떤 조건이 "search" | 검색 단계가 주로 늘어남 → C1·C2와 무관한 쪽이라 C3 새 기여 근거로 쓰지 않음(기록만) |
| J3 A2 vs A3 "단계별 경합 모양이 다름" | **C2(BC1) 적용이 동시 실행 경합을 바꾼다 = C2 특성을 쓰는 C3 후보의 근거** → 다음 단계로 진행(어떤 단계가 얼마나 바뀌는지로 후보 정의) |
| J3 A1 vs A2 "단계별 경합 모양이 다름" | **배치(C1)가 경합을 바꾼다 = C1 특성을 쓰는 C3 후보의 근거** → 다음 단계로 진행 |
| J3 두 비교 모두 "차이 확인 안 됨" | warm에서는 C1·C2가 C3 동작을 바꾸지 않는다 → **warm에서 C1·C2 연계 C3 새 기여는 버림.** 남는 것은 cold(캐시 상주 인식 스케줄링, 지현 환경 필요)뿐 |
| J1 꺾임 위치가 조건마다 다름 | "최적 동시 수가 C1·C2에 따라 바뀐다"는 관찰(팀 문서 ③)로 기록. 다만 이를 상한 자동 조절로 쓰는 것은 교수님 피드백(고정 상한 조절 X)과 부딪히므로 단독 후보로 삼지 않음 |
| 판정 불가(무효 칸으로 J2·J3 못 함) | 결정 보류. 무효 원인을 고친 뒤 같은 규칙으로 다시 측정할지 사용자와 정함 |

말할 수 없는 것: 이 실험만으로 "C3 기법이 성능을 올린다"는 결론은 나오지 않는다(기법을 적용하지 않음, warm, 경향 탐색).
